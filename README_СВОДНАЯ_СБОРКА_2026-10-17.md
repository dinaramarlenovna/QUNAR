# QŪNAR v0.8.1 - сводная рабочая сборка 17.10.2026

## Назначение
Полный исходный проект для следующего этапа разработки и тестирования.
Основа: `QUNAR_v0_8_1_latest(1).zip` (присланная пользователем).
Поверх основы последовательно внесены накопленные изменения: QA50, A7, A5 цены,
A5 затраты, A5 исследовательская индексация, A3 FAO-56; последняя итерация:
справочные FAO коэффициенты способов орошения и Kc по фазам роста.
Последняя версия каждого изменённого файла использовалась целиком,
а не слияние несовместимых кусков `app.py`.

## В этой единой сборке содержится
- A1: частичный учёт и сравнение выбросов для вводимых производственных сценариев.
  Автоматическое построение полного профиля выбросов оптимальной структуры
  по культурам без пользовательской информации не подтверждено.
- A2: пространственные пробы NASA по ячейкам, пересекающим полигон;
  при мелком поле может быть одна ячейка. Реальное подключение сервиса не проверено.
- A3: отдельный FAO-56 расчёт ET0, ETc, эффективного дождя и подачи воды;
  CMIP6, NASA POWER и выбранный полив. Не меняет официальные нормативы
  и жёсткий водный лимит оптимизатора автоматически.
- A4: CMIP6 SSP2-4.5 / SSP5-8.5, аномалии температуры и осадков,
  экстремальная жара >35, >40, >45 °C; проверки исходных CSV обязательны.
- A5: цены производителей Туркестанской области 2022-2025, без подмены
  конфиденциальных данных; пользовательские/постатейные затраты;
  исторические страховые нормативы 2015 и проверенные индексы только
  как исследовательский источник, не автоматически как себестоимость 2025.
- A6: предупреждения о прогнозной надёжности. RF и опубликованные
  показатели валидации оставлены без переобучения.
- A7: отдельный экспериментальный профиль водно-климатических весов
  на основе открыто описанного преобразования результатов опроса;
  не репрезентативно оцененные предпочтения всей области.
- A8: строгие ограничения оптимизации; дополнительно требуется независимый
  воспроизводимый сравнительный кейс «до/после».
- A9: пользовательская урожайность прежде справочной урожайности района
  за предыдущие три года; прогноз Random Forest выводится отдельно.

## Новое: доказуемые справочные показатели орошения
`core/irrigation_evidence.py`, `tests/test_irrigation_evidence.py`, UI в `app.py`.

1. FAO Irrigation Water Management Training Manual 4, Annex I, Table 8:
   бороздовой/поверхностный: 0,60; дождевание: 0,75; капельное: 0,90.
   https://www.fao.org/4/t7202e/t7202e08.htm
2. Методика РК: приказ №116-НҚ (2025), с изменениями №191-НҚ (2026):
   https://adilet.zan.kz/rus/docs/V2500036251
   https://adilet.zan.kz/rus/docs/V2600039130
   Для капельного указано 0,90–0,98 при зависимости от почвы,
   культуры и технологии, поэтому единый автоматический коэффициент РК
   для всех полей не устанавливаем. Значения FAO являются сценарными,
   а не установленными для конкретного хозяйства.
3. FAO Irrigation Water Management Training Manual 3, Tables 7 и 8:
   стадийные Kc и ориентиры длительности фаз для ряда однолетних культур.
   https://www.fao.org/4/S2022E/s2022e07.htm
   Пользователь выбирает дату посева и может изменить сроки каждой фазы.
   Расчёт Kc апреля–сентября на основе четырёх стадий является упрощённым
   справочным сценарием; локальная фенология не валидирована. Рис,
   многолетние насаждения и иные неуказанные культуры не получают
   неподтверждённого автоматического Kc.
4. Смешанный полив: ввод долей площадей по бороздовому, дождеванию
   и капельному способам. Эффективность рассчитывается через суммирование
   подаваемой воды по долям площади (гармоническое взвешивание η);
   нужен общий чистый расход воды на гектар. Неполные доли отклоняются.
5. Сравнение способов полива выполняется при ОДНОЙ И ТОЙ ЖЕ чистой
   потребности культуры: Wgross = Wnet / efficiency.
   Расчётная экономия подачи воды не равна фактически достигнутой экономии
   или уменьшению безвозвратного потребления воды.
6. Для FAO-56 используется эталонная ET0, а не истинная проверенная
   водопотребность конкретного поля. Нормы приказа №108-НҚ отдельно.

## Как использовать
Это полный архив: старые «частичные» патчи поверх него отдельно применять
НЕ требуется, иначе можно потерять более поздние исправления.
Сохранить резервную копию опубликованного проекта. Развернуть новый полный архив
в тестовом каталоге или отдельном тестовом Streamlit приложении, установить
`requirements.txt`, запустить приложение, проверить функции вручную,
сопоставить экспорты с экраном. Только затем обновить основной сайт.
