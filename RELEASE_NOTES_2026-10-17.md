# QŪNAR v0.8.1 - объединённый патч к коду, 17.10.2026

## Основа
Архив пользователя `QUNAR_v0_8_1_latest(1).zip`. В ZIP ниже только новые и изменённые файлы по сравнению с ним. **Не заменять папки целиком**: разложить файлы с сохранением путей в корне проекта.

## Реализовано
1. `app.py` - интеграция пользовательской 3-летней справочной урожайности в экономический расчёт (А9), отдельно от прогноза Random Forest. При расчёте на 2025 год 2025-й в справочник не попадает. При отсутствии достоверного ряда прибыль не фабрикуется.
2. `core/cmip6_scenarios.py` и `data/cmip6/*.csv` - подстановка региональных аномалий World Bank CCKP для SSP2-4.5 и SSP5-8.5, 2040-2059, с температурой/осадками и числами жарких дней >35/>40/>45 °C. Значения аномалий осадков берутся именно из режима Anomaly, не смешиваются с разностью агрегатов Mean. В режиме оптимизации климатический стресс - **эксперимент**, а не валидированный прогноз будущей урожайности.
3. `core/nasa_polygon.py` - при ретроспективной оценке выбранного пользователем полигона NASA POWER запрашивается по номинальным пересекающимся ячейкам и рассчитывается взвешенное по площади приближение. Для мелких полей одна климатическая ячейка - ожидаемое поведение. Лимит до 16 ячеек с предупреждением и возвратом к точечной оценке при отказе пространственного режима. Историческая ML-панель не менялась.
4. `core/carbon_scenarios.py` - частичный сценарный инвентарь прямых выбросов N₂O от азота, CO₂ от дизеля, CO₂e от электроэнергии, опционально метан пищеварения. Для двустороннего сравнения требуются явно подтверждённые пользовательские значения и идентичные границы учёта. Если есть животные, коэффициент CH₄ >0 обязателен. **Это не полный углеродный след и не подтверждённый эффект внедрения**.
5. `core/water_climate.py` - только чувствительность температурного множителя формулы Харгривса, **не** расчёт ETc и не изменение официальных норм орошения или водного лимита.
6. `core/forecast_reliability.py` - диагностические предупреждения по ранее опубликованным показателям по культуре и leave-one-district-out. Это правила показа, а не новые вероятности или переобучение.
7. `core/optimizer.py` - строгие ограничения количества культур, максимальной доли и доступной воды сохранены, плюс пользовательский профиль весов климата/воды. Сценарные веса не выдаются за веса опроса. `core/optimization_guard.py` - независимая финальная проверка решения до показа/экспорта.
8. Восстановлены `core/irrigation_economics.py` и `core/irrigation_report.py`, отсутствовавшие в последнем полном ZIP, но импортируемые его `app.py`.
9. Точечная локализация выводимых в отчёт новых CMIP6/GHG показателей по языкам KK/RU/EN и аудит входных величин (включая метан при наличии). Сравнение CO₂e требует одинаковых коэффициентов и расчётных периодов (апрель-сентябрь или календарный год). Контроль исходных/сценарных нулевых выбросов требует подтверждения ввода.

## Проверки
- После дополнительных проверок: 50 headless-тестов успешно (включая 7 новых тестов учёта CO₂e). Тестирование без установленных библиотек Streamlit использует только временную заглушку декораторов кеширования, не интерфейса. Среди них тесты ограничений оптимизатора, отсутствие фальшивой прибыли при невыполнимом водном лимите, перенос данных CMIP6, расчёт выбросов, полигон, справочная урожайность и генерация PDF/Word/Excel на 3 языках.
- `app.py` и модули `core/*.py`: синтаксис Python проверен.
- Скрипт бенчмарка для 2025 года: 68 сопоставимых наблюдений, MAE 8.8132 (среднее 3 лет), 9.5588 (последний год), 14.6852 (CatBoost). CatBoost в основной прогноз не включён.
- Историческая панель, `core/ml.py`, исходная регрессионная валидация и `core/reporting.py`: **по байтам совпадают с полным исходным архивом**.

## Ограничения и что не выдавать за реализованное
- Streamlit и `streamlit-folium` отсутствуют в этой рабочей среде, а скачивание пакетов недоступно. Поэтому **браузерный тест Streamlit НЕ проводился**. Не утверждать, что текущая сборка прошла публикационный smoke test.
- Не добавлены абсолютные цены реализации из БНС: присланные XLS содержат индексы, которые нельзя подставлять вместо цены в KZT/t.
- Не добавлены автоматически рассчитанные веса на основе опроса: доля ответов не является напрямую валидированным весом индекса.
- Не добавлено «реальное увеличение полива на 4-5%»: для корректного ET0/ETc требуется отдельная методика и дополнительные погодные данные; доступен только маркированный температурный прокси.
- Не реализована автоматическая экономия CO₂e по рекомендациям структуры без входных расходов для каждой культуры: пользователь должен явно задать активность в базовом и сценарном вариантах.
- Невозможно считать реальные сокращения выбросов BIO-AGRO или фактический экономический эффект по модельным сценариям.
- Видимая версия сайта остаётся `v0.8.1`.

## Порядок объединения и обновления сайта
1. Сделать резервную копию опубликованной рабочей сборки.
2. Распаковать этот ZIP в КОРЕНЬ полной сборки пользователя (не удаляя остальные файлы) с заменой по относительным путям.
3. Локально установить `requirements.txt`, выполнить `python -m pytest -q tests` и `streamlit run app.py`.
4. Пройти на 3 языках минимум: Assess My Farm (ручные/нулевые вводы), карту с малым/большим полигоном, Optimize Farm Structure с допустимым/невозможным лимитом воды, SSP2-4.5/SSP5-8.5, GHG с одинаковым и неполным набором входов, PDF/Word/Excel.
5. После успешного локального браузерного smoke test - одна публикация на Streamlit.

Файлы `tests/` нужны только для тестирования, на работающий сайт не обязательны. Никакие исторические данные и модельные артефакты менять не нужно.
